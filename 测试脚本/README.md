# 回归验证脚本说明

> 新版优先使用后端目录的 `npm run test:integration`：自动创建临时数据库，完成 43 项真实 HTTP/MySQL 检查后清理（2026-11-02 验证通过）。下列旧脚本已适配新请求字段，但本轮未重跑；部分脚本异常退出时不能保证清理，勿在真实业务环境执行。

这些脚本用于**验证修复后的真实行为**（走真实 HTTP 接口 + 直连 MySQL 断言），
与 `项目/lesson15/shopDemoBackend/controls/__tests__/` 下的单元测试（纯 mock）互补。

## 运行前提

1. 后端已启动：`cd 项目/lesson15/shopDemoBackend && npm start`（监听 3000）
2. 前端已启动：`cd 项目/lesson15/lesson15 && npm run dev`（监听 5173）
3. MySQL 已启动且 `vue-demo12` 库可访问

## 运行方式

```powershell
# 逐个运行
node "测试脚本\01-订单事务与计价.js"

# 全部运行
Get-ChildItem "测试脚本\*.js" | ForEach-Object { node $_.FullName }
```

## 推荐用法：配合数据哨兵跑

```powershell
# 1. 记录当前数据库基线
node "测试脚本\00-数据快照.js" save

# 2. 跑任意回归脚本
node "测试脚本\01-订单事务与计价.js"

# 3. 检查数据是否被改动（退出码 0 = 无漂移）
node "测试脚本\00-数据快照.js" check
```

`00-数据快照.js` 会逐行比对 **购物车、订单、订单明细、商品库存/上下架、用户角色**，
任何一处被脚本改坏都会立即报出来 —— 建议每次跑完回归都执行一次 `check`。


## 重要说明

- **脚本会写数据库**（下单、加购等），但每支脚本末尾都会**自动还原**测试数据，
  并在最后断言「订单/明细/购物车/商品数量与测试前一致」。
- 断言失败时脚本仍会执行还原流程，但为避免误伤生产数据，**建议先备份数据库**
  （`mysqldump` 导出到 `_backup/`）再运行。
- 脚本通过 `createRequire` 借用后端目录下已安装的 `mysql` 驱动，因此**必须保持
  当前目录结构不变**（脚本位于工作区根目录的 `测试脚本/` 下）。

## 已知待验证项（尚未修复）

- 注册页两次密码一致性校验目前是**前端行为**，脚本无法直接验证，需在浏览器手工确认。
- 路由守卫的 token 过期逻辑同理，需修改浏览器 `localStorage.exp` 为过去时间后手工确认。
